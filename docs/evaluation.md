# Evaluation protocol

Run `.venv/bin/python -m evaluation.run` from the repository root. Outputs
`.local/results.mock.json` with 100 observations (50 cases x 2 methods), stage
latencies, failures, selected IDs, token counts when available and aggregate metrics.
Mock reports are labeled `mock_harness_only` and kept outside version control.
They measure harness and selection behavior, not actual LLM performance. CI
publishes its generated report as an artifact.

Cases are generated by `python -m evaluation.build_cases`. All companies, facts,
people and sources are fictional. Labels are synthetic author expectations based on
explicit technology evidence and contact role/company association. Fifty cases include
aliases, realistic multi-sentence descriptions, multiple requirements, unsupported
Kubernetes/Helm requirements, irrelevant shared-word facts, retired/unapproved facts,
long titles, leadership contacts and former-employment distractors. These remain
controlled-vocabulary labels favoring explicit matching, not independent human judgments.
Add blinded human labels and broader semantic/negation cases before quality claims.

`evaluation/baseline.py` preserves the prior role-only, first-12-facts selection
contract in a small adapter. The actual repository at inspection rendered whole
facts with deterministic framing, not free-form model-written notes. Tests verify that drafting requests a structured fact-selection plan and that
only approved whole facts enter the deterministic renderer.

Real-model evaluation is optional:

```
OLLAMA_URL=http://127.0.0.1:11434 .venv/bin/python -m evaluation.run --real-model --output .local/results.real.json
 .venv/bin/python -m evaluation.run --real-model --embeddings --output .local/results.embeddings.json
```

Use the same model/version, cases, token/context budget and machine for comparisons.
Record Ollama model digests and host details beside local results. Real runs can
make hundreds of local calls and exact-length generation may fail. Failures remain
in the denominator. Never label a mocked CI run as real model performance. The `--embeddings` option forces requests regardless of collection size. Results count
embedding calls, retrieval methods and lexical fallback cases separately. Embedding
failure uses lexical retrieval with a warning; fallback observations are not evidence
of embedding quality. CLI embedding runs require --real-model. Tests substitute a
fictional provider and are not quality results.

For a shorter real-provider smoke check, run:

```
.venv/bin/python -m evaluation.run --real-model --embeddings --limit 3 --require-success --output .local/results.real-smoke.json
```

`--limit` selects the first N corpus cases, and results include corpus size and an
explicit partial-run flag. A small smoke run does not establish overall quality.
Real runs record model names/digests when available, embedding version, host architecture
and Python version. The real-run default output is `.local/results.real.json` so it
does not overwrite the local mock result. `--require-success` writes the report
and exits nonzero on any case failure or requested embedding fallback. Without this
flag the report can contain failures even when the command exits successfully.

Metrics:

- Fact precision/recall: set intersection of selected fact IDs with expected IDs.
- Contact NDCG: binary expected relevance, logarithmic positional discount.
  Ranking algorithm is unchanged between systems; mock ranking is a title heuristic.
- Unsupported-claim rate: regex identifies first-person experience spans beginning
  “I built/led/maintained/implemented/developed/have experience”; the entire span must
  equal an approved fact. Numerator is unmatched spans; denominator is recognized
  spans. No spans means null, not perfect factuality. This check misses claims with
  other wording, implied qualifications, and contact/application errors. A zero
  score does not establish that every claim is supported.
- Failure rate: extraction, generation, provider or validation exceptions / cases.
- Timing: local wall-clock milliseconds end-to-end and per stage. Mock generation
  concatenates exact facts and does not exercise model latency. No speedup claim.
- Calls/tokens: actual instrumented calls and Ollama prompt_eval_count/eval_count;
  unavailable token counts stay absent. Mock model calls are zero.

The application requires explicit named technology evidence/recognized aliases. Tags and
embedding similarity cannot prove qualifications. Broad requirements receive supported,
uncertain or unsupported assessments; duration/scope needs evidence. Unknown skills can
be conservatively unsupported. Supporting records, excerpts and reasons remain available
for review. “Unsupported” means missing collection evidence, never proof of missing skill.

Both methods use the same final six-fact/2,800-character bounds. Optional real runs use
the same generation model/interface, exact-200-character note requirement and 1,200-character
DM limit; the historical role-only baseline still intentionally sees only its first 12
candidate facts. Mock generation concatenates facts and does not test those rendering
constraints. Precision/recall report selection, not end-to-end draft quality in mock mode.

Acceptance/editing is persisted per message. Applying only a note does not attribute
changes in an untouched DM. Legacy combined observations remain stored and are reported
separately. Before new observations, the API returns insufficient data and null rates.
See [verification](verification.md) for measured results and limits.

Langfuse is included in the locked dependencies but disabled by default. To enable
it, set LANGFUSE_ENABLED=true,
LANGFUSE_PUBLIC_KEY, LANGFUSE_SECRET_KEY and LANGFUSE_BASE_URL using secrets injection.
Use an independently managed Langfuse instance; no telemetry server is required for
the demo. Default observations include stage/model/prompt version, timing, retries,
failure indicator and available tokens. Raw content is disabled; enabling
TRACE_RAW_CONTENT=true explicitly permits model input (including facts and sources)
to leave the machine. Disable LANGSMITH_TRACING; this project does not enable it.
Checkpoint files and benchmark outputs are private artifacts, not telemetry.

Extraction now uses model-selected indexes into exact server-owned source spans. A separate narrow technology-use requirement can accompany an uncertain broad responsibility. See [verification report](verification.md) for the actual three-case provider result and its limits.
